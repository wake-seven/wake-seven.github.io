# WAKE-SEVEN 操作・解法メモ

更新日: 2026-09-27

公開版 [WAKE-SEVEN](https://wake-seven.github.io/) をブラウザで再開・解答するときの記録。問題ごとの固定解答やドラッグ座標には依存しない。ブラウザに進行状況が保存されている場合も、まず画面を見て現在地点を確かめる。

## ゲームの数学モデル

- 盤面は中央1か所と周囲6か所、計7個のだるま。それぞれの向きを `0 / 1 / 2` の3値で表す。盤面全体は `x ∈ (Z/3Z)^7`、つまり三進数7桁の状態で、符号は `s = Σ(x[i] × 3^i)`。完成状態は全桁0、符号 `s=0`。
- 回転グループは6つ。各グループは中央のだるまと周囲の隣り合う2体からなる。
- 1回の「くるり」は、その3体の場所を循環させると同時に、向きを全員ぶん同じ方向へ1段（120°）進める。逆回転はその逆変換。1回のくるりは3回繰り返すと元の状態に戻る。
- したがって、各状態からの候補手は6グループ×2方向＝12通り。現在状態から `s=0` まで幅優先探索（BFS）し、最短手数と最短経路を得る。

## 到達できる状態と難しさ

- 向きの数字の合計を3で割った余りは、操作しても変わらない。1手で対象の3体の数字がそれぞれ1増減するため、合計の変化は `+3` または `-3`（mod 3では0）。完成盤面から解けるのは合計が `0 mod 3` の状態だけ。
- 全状態は `3^7 = 2187` 通り。そのうち合計が `0 mod 3` の状態は `3^6 = 729` 通りで、ゲームの6操作をBFSするとこの729状態すべてに到達する。
- 完成状態からの最短手数ごとの状態数は、0手: 1、1手: 12、2手: 102、3手: 402、4手: 212。合計729で、最長でも最短4手。平均最短手数は `2270/729 ≈ 3.11` 手で、距離3〜4の盤面が約84.2%を占める。
- 盤面を回転・反転して重なるものを同一視する対称群は六角形の二面体群 `D6`（12変換）。反転では位置の鏡映に加えて向きも反転し、三進値 `1` と `2` を交換する（`x → -x mod 3`）。
- Burnsideの補題で同値類を数える。恒等変換が729状態を固定し、回転±60°は各3、±120°は各9、180°は27を固定する。反転軸が向かい合う頂点を通る3変換は各9、向かい合う辺を通る3変換は各27を固定する。固定数の合計は `729 + 2×3 + 2×9 + 27 + 3×9 + 3×27 = 888`。`888 / 12 = 74` 類で、完成盤面の1類を除けば未完成盤面は73類。
- 公開版の悟りへの道73問を同じ D6 正規化で照合した結果、重複はなく、完成盤面以外の73同値類をちょうど1問ずつ網羅している。つまり悟りへの道は、対称性でまとめた全未完成盤面の代表を一巡する構成。
- 向きの反転をせず、位置だけを回転・鏡映する数え方では92類（完成を除くと91類）になる。73を得るには、鏡映時に向きも反転することが必要。
- 計算上は小さな探索だが、人間には7体の向きと「場所の循環＋向きの変化」を同時に追い、12通りから正しい手を選ぶ必要がある。3手・4手が難しく感じるのは自然で、2手・3手の形を覚えることは探索を頭の中で素早く行うパターン認識になる。
- 問題を新しく作るなら、状態をランダムに選ぶだけでは解けない盤面（合計が1または2 mod 3）を混ぜる可能性がある。完成状態から操作を重ねて生成するか、合計条件を確認する。出題したい最短手数は、スクランブル回数ではなくBFSの距離で判定する。

## ブラウザ上での解答手順

1. ステージ名、問題番号、盤面の `data-state`、盤面フェーズ（操作可能な `ready` 状態か）を読む。
2. 状態から最短経路を計算し、最初の一手のグループと向きを決める。
3. 現在の表示領域で盤面の支点とグリップを見分け、短いドラッグを一手だけ行う。以前の画面で使った座標をそのまま流用しない。
4. アニメーション終了後に `ready` と盤面状態を確認する。予定した次状態と一致したときだけ次の手へ進み、違っていれば盤面を読み直して解き直す。
5. 完成後は画面に表示された通常の進行ボタンや確認を使い、次の問題・ステージへ進む。問題番号と盤面を再確認してから同じ手順を繰り返す。

## 操作上の注意

- 画面サイズ、ブラウザの表示領域、盤面の角度でドラッグの反応は変わる。再開時や表示条件が変わったときは、支点・グリップを画面から見直して一手ずつ照合する。
- 現在の表示条件では、軸3の一方向の操作が外側のグリップからだと逆向きに判定されることがあった。軸に沿って支点寄りから始めると改善したが、これは画面依存の観察なので、実行後の `data-state` で必ず確認する。
- 速解きや一部の道場問題では最短手数の条件がある。複数の最短経路から、ドラッグ方向を確実に判別できる経路を選ぶ。
- 問題固有の状態番号、解答列、画面座標の一覧は保持しない。盤面から毎回計算し、実際の画面遷移で答え合わせする。
